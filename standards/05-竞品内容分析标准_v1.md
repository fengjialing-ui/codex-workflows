# 竞品内容分析标准 v2（多类型融合版）

## 1. 目的与边界

竞品分析用来校正意图、发现必须覆盖的内容和可验证差异化；不用于复制结构、臆测排名原因或把竞品主张升级为事实。分析结论只对当前主题、市场、语言、日期和页面类型有效。

## 2. 共同研究规则

- 记录该市场/语言/设备下的自然 SERP 前 10 名，并深度分析 3–5 个意图和页面类型相符的样本。
- 每个样本记录 URL、排名、抓取日期、页面类型、版本/更新时间（如适用）和纳入/排除原因。
- 单页分析答案路径、内容模块、问题/实体覆盖、步骤或解释深度、证据、限制、UX 和转化边界。
- 横向输出 `Must Cover`、`Must Improve`、`Differentiate`、`Product Proof`、`Avoid`、`Verify`，并为每项附来源或证据位置。

## 3. 依类型增加的分析维度

| 类型 | 额外分析重点 |
| --- | --- |
| How-to | 方案池、场景分流、步骤、异常处理和选择逻辑 |
| Top | 候选范围、评估维度、排序依据、披露和更新性 |
| VS | 对象版本、同维度对比、获胜条件和适用人群 |
| 泛主题 | 内容子模式、实体关系、定义深度和场景边界 |
| Alternatives | 用户替代动因、迁移成本、替换范围和遗漏对象 |
| What Is & Specs | 定义口径、规格表、版本/单位、引用源和限制 |

## 4. 机会矩阵如何进入文章

- `Must Cover` 进入 Brief 的必答问题或核心模块。
- `Must Improve` 转换成更清楚的步骤、解释、表格、边界或来源要求。
- `Differentiate` 必须是可交付的原创价值，如明确的决策框架、已验证资料整合或场景分流；不能只写“更全面”。
- `Product Proof` 仅在产品角色已获批准时使用，且不等于预设排名、胜方或最佳方案。
- `Avoid` 和 `Verify` 必须在大纲和 QA 中保留为显式约束。

## 5. 阻断条件

没有当前 SERP、市场/语言或日期；只抓标题不读正文；少于 3 个深度样本却无原因；不区分事实与竞品营销；没有机会矩阵；将竞争对手的结构/产品排序直接复制到正文，均不得进入 Brief。
