# 高转化 How-to 文章内容结构标准 v4（融合版）

> How-to 专属结构以 `07-How-to文章内容生成工作流_v5.md` 为完整执行规范；本文件保留旧入口并定义不可省略的结构和转化边界。不得用于 Top、VS、Alternatives、泛主题或 What Is 文章。

## 1. 文章目标

先让用户完成核心任务，再帮助他在多个真实可行方案中选择。转化来自场景匹配、可执行步骤和有边界的证据，不来自强插产品、夸张承诺或固定的产品排序。

## 2. 写作前的必备决策

- 明确用户任务、素材/设备条件、结果预期、风险和能力差异。
- 基于当前研究建立候选方案池；Method 数量由场景覆盖决定，不设固定模板。
- 产品只有直接处理核心任务时才可为 `formal_method`；只解决相邻需求时为 `ultra_tip`，无关或证据不足则 `excluded`。
- “Best”或“Most Reliable”等定位必须有可追溯比较依据；没有证据时使用场景化、条件性的建议。

## 3. 推荐答案路径

1. 唯一 Title 与 H1
2. 简短 Introduction：问题、对象、承诺与边界
3. Quick Answer：先给可选路径和选择条件
4. 准备/风险提示（仅任务确有需要时）
5. Methods Overview：方案、最适合的场景、门槛、时间/成本、限制
6. Method 1 至 N：同级展开
7. How to Choose：按 use case 分流
8. Common Mistakes / Troubleshooting（按需）
9. FAQ
10. Verdict：按场景而非单一广告结论给建议
11. CTA：放在价值、步骤和边界解释之后

文章可因意图删减非核心模块，但不能删除 Quick Answer、主要解决路径、选择逻辑或限制说明而不记录原因。

## 4. 每个 Method 的最低要求

每个 Method 均说明：适用对象与场景、前置条件、具体步骤、预期结果、局限/风险及选择理由。步骤必须包含“操作 + 为什么 + 当前场景的建议”，而不是 Download/Upload/Export 式空壳。

正式产品 Method 还必须按 `场景问题 → 已核验功能/设置 → 操作 → 可合理预期的结果 → 边界` 组织。没有真实测试时，案例只能称为“示例工作流”或“建议测试方案”。

## 5. Ultra-Tip 边界

Ultra-Tip 只能在正式主任务路径完成之后出现，必须标明其补充性质、相邻场景、产品不解决的主任务部分、步骤与格式/登录/隐私/版权/版本限制。它不计入 Method 数量、不出现在 Quick Answer 或 Methods Overview，也不能代替任何主方案。

## 6. 结构阻断条件

- 多方案需求却无研究依据地只给单一路径。
- 产品在大纲完成后才作为广告章节追加。
- 产品与内容对象或核心任务不匹配却被写成正式 Method。
- 标题多 H1、层级跳级，或用标题层级伪装视觉样式。
- 比较、案例、评分或“最佳”结论无证据。
- 将本结构套用到非 How-to 类型。
