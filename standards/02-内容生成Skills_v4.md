# 内容生成 Skills v4.1

## 1. 核心原则

- 先关键词和初步意图，再分析竞品并综合判定最终搜索意图
- 先理解排名内容做了什么，再决定 Methods 和差异化结构
- 自有产品从方案研究阶段进入 Methods 矩阵
- 产品 Method 与其他 Method 并列，但用更完整的场景、步骤和证据建立优势
- 先规划 H 标签树，再生成大纲和正文
- 先校验产品事实，再写产品结论
- 完成全文后按标准回审，不通过则回流到责任 Skill

## 2. Skills 定义

### 2.1 SEO 关键词分析 Skill

输入：

- 主关键词
- 目标市场与语言
- 目标页面和站内 URL
- PAA、搜索下拉、相关词和已有关键词数据

输出：

- 主关键词、次关键词、长尾词、语义词和场景词
- 用户问题与 FAQ 词
- 关键词与 Title、H1、H2/H3、正文和 FAQ 的映射
- 关键词冲突和页面蚕食风险

失败条件：

- 只有主关键词，没有场景词和问题词
- 关键词没有映射到章节

### 2.2 初步搜索意图假设 Skill

输入：

- 关键词分析结果
- SERP 页面类型和用户问题

输出初步假设：

- 核心任务
- 主要与次要意图
- 用户场景、预算、设备、能力和结果预期
- 用户希望比较的方案类型
- 必须回答的问题
- 转化机会与不可越过的意图边界
- 用于筛选竞品的页面类型和相关性条件

失败条件：

- 只标注 Informational/Commercial，不解释真实任务
- 没有给 Methods 研究提供场景条件

初步假设不能直接作为最终意图结论。

### 2.3 SERP 样本选择 Skill

输入：

- 关键词分析
- 初步搜索意图假设
- 目标市场、语言和设备

输出：

- 自然搜索结果前 10 名
- 3 至 5 个核心深度分析样本
- 官方、论坛、视频、工具页等补充样本
- URL、排名、页面类型、抓取日期和选择/排除理由

失败条件：

- 样本与目标页面类型或意图不一致
- 没有记录市场、语言和日期

### 2.4 竞品内容分析 Skill

按照《竞品内容分析标准 v1》执行。

逐页分析：

- 用户意图与内容任务
- Title、H1 和 H2/H3 结构
- Quick Answer、Methods、步骤、比较、场景、案例、FAQ 和 Verdict
- 关键词、长尾词、PAA、痛点词、技术词和实体
- 可执行深度、参数、异常处理和边界
- E-E-A-T、测试、来源和原创信息
- 产品 Method、转化逻辑和 CTA
- 阅读体验和视觉内容

横向输出：

- 竞品共性
- Methods 汇总与去重
- 内容和关键词覆盖矩阵
- 高排名页面在内容层面可能做对的事情
- 内容差距、事实风险和体验问题
- Must Cover、Must Improve、Differentiate、Product Proof、Avoid、Verify
- 给最终搜索意图、Methods、Brief 和大纲的明确指令

失败条件：

- 只提取标题或摘要
- 没有分析排名内容为什么可能表现好
- 没有形成差异化机会
- 结论没有对应 URL 或内容证据

### 2.5 搜索意图综合判定 Skill

输入：

- 初步搜索意图假设
- SERP 样本
- 竞品内容分析
- PAA、相关搜索和论坛需求

输出：

- 最终主意图和次意图
- 用户真正需要的内容与决策问题
- 必须覆盖的场景和内容模块
- 不应扩展的意图边界
- Methods 研究指令

必须明确初步假设被确认、修正或否定了哪些部分。

### 2.6 解决方案研究 Skill

输入：

- 搜索意图综合判定
- SERP、官方资料、论坛与竞品内容
- 产品事实知识库
- 竞品内容分析与最终搜索意图

执行：

1. 收集官方、免费、手动、在线、桌面、专业和论坛验证方案
2. 将自有产品加入同一个候选方案池
3. 去重，并排除无效、过时、危险或不符合意图的方案
4. 记录每个方案的证据来源

输出：

- 候选方案池
- 来源与可信度
- 覆盖的用户场景
- 排除项及排除理由

### 2.7 Methods 决策 Skill

输入：

- 搜索意图综合判定
- 候选方案池
- 产品事实知识库
- 竞品 Methods 去重结果
- 内容机会矩阵

输出一个方法矩阵：

| 字段 | 要求 |
|---|---|
| method_id | 唯一编号 |
| method_name | 方法名称 |
| is_own_product | 是否为自有产品 |
| target_scenario | 适用场景 |
| user_type | 适合用户 |
| problem_solved | 解决的问题 |
| requirements | 前置条件 |
| steps_summary | 步骤摘要 |
| expected_result | 预期结果 |
| strengths | 优点 |
| limitations | 限制 |
| evidence | 依据 |
| recommended_order | 建议顺序 |
| positioning | Best Overall / Best Free / Best Manual 等 |

决策规则：

- 禁止使用固定数量模板；先评估完整候选池，再决定最终 Method 数量
- 通常选择 2 至 4 个能够覆盖不同场景的方法，但该范围不是硬性生成目标，少于或超过时必须输出依据
- 产品必须进入候选池接受评估，只有适配当前问题时才作为一个 Method 进入最终矩阵
- 产品不能作为 Methods 之外的“额外推荐”
- 不得固定产品排序；`recommended_order` 必须由意图匹配、有效性、门槛、风险和叙事逻辑共同决定
- 只有一个 Method 时必须输出无其他可行方案的证据
- “Best”定位必须由矩阵比较支持

失败条件：

- 产品行缺失
- Methods 只是不同工具名称，没有场景差异
- 多方案意图只输出一个 Method
- 先指定产品为最佳，再倒推理由

### 2.8 场景化产品 Method 设计 Skill

该 Skill 替代“正文完成后植入产品”的做法，在 Brief 和大纲前完成产品 Method 设计。

输入：

- 产品所在的方法矩阵行
- 产品白皮书和事实知识库
- 用户场景与关键词
- 可用案例、测试数据和图片资料
- 竞品 Product Proof 与产品转化分析

输出：

- 场景诊断
- 普通方法不足
- `场景问题 -> 功能/模型 -> 设置 -> 结果 -> 边界`映射
- 完整步骤：准备、导入、选择功能/模型、设置、预览、调整、导出
- 每一步的场景化说明
- 专业案例或明确标记的示例工作流
- 优点、限制和与其他 Methods 的差异
- CTA 位置和文案依据

失败条件：

- 只有通用功能列表
- 步骤无法由用户执行
- 功能或参数未在知识库中确认
- 被称为最佳方案但没有比较依据或案例

### 2.9 Content Brief 生成 Skill

必须写入：

- 页面目标和目标用户
- 搜索意图与必须满足的场景
- 完整方法矩阵
- 每个 Method 的定位和顺序
- 产品 Method 的场景、步骤、案例和边界要求
- 关键词与章节映射
- Quick Answer、比较、use case、FAQ、Verdict 和 CTA 要求
- 验收与退回条件
- 竞品共性、内容差距和差异化要求
- 至少一个可明确交付的超越点

Brief 中不再使用模糊的“产品植入点”，改为“产品 Method 规格”。

### 2.10 H 标签规划 Skill

输出：

- 唯一 H1
- H2/H3 标题树
- 每个 Method 的同级标题
- 标题与关键词映射
- 非标题模块清单

硬性检查：

- H1 数量等于 1
- 不跳级
- Quick Answer、Introduction、CTA 和普通强调语不标为 H1
- 同级 Methods 使用同级标题

### 2.11 大纲生成 Skill

根据 Brief、方法矩阵、产品 Method 规格和 H 标签树生成大纲。

产品 Method 必须同时出现在：

- Quick Answer 或方法总览
- Methods 正文
- 比较表
- use case 选择
- Verdict

### 2.12 大纲审核 Skill

阻断条件：

- H1 不唯一或标题层级不正确
- 方法数量与矩阵不一致
- 产品不在 Methods 中，而被放到独立广告章节
- 产品 Method 缺少详细步骤或专业案例计划
- “Best”结论在大纲中没有证据链
- Quick Answer、use case、比较或 Verdict 缺失
- 大纲只是复制竞品结构，没有执行差异化要求

### 2.13 分章节正文生成 Skill

- 按已批准大纲逐章生成
- 每个 Method 遵循统一 Method 模板
- 产品章节调用“场景化产品 Method 设计 Skill”的结果
- 不允许在正文阶段临时删除 Method 或另加产品推荐章节
- 生成产品步骤时引用已校验的产品事实

### 2.14 产品 Method 证据审核 Skill

检查：

- 场景是否具体
- 功能是否与问题直接对应
- 步骤是否包含动作、原因和场景设置
- 案例是否含输入、目标、操作、结果和限制
- 测试数据与评价是否有来源
- 专业优势是否由比较证据支持

### 2.15 事实校验 Skill

检查功能、模型、格式、平台、步骤、参数、限制、版本、价格、案例和结果表述。无依据内容必须删除、降级为建议或标记待确认。

### 2.16 SEO 优化 Skill

优化 Title、Meta、唯一 H1、H2/H3、关键词布局、FAQ、内链和图片 alt。不得为了埋词改变已批准的方法逻辑。

### 2.17 标准回审 Skill

逐条对照标准，输出：

- 通过项及证据位置
- 未通过项
- 严重度
- 责任 Skill
- 局部修复指令

重点回审：

- 搜索意图是否由 Methods 满足
- 产品是否作为正式 Method
- 产品场景、步骤和案例是否完整
- “Best”结论是否成立
- H1 是否唯一
- 竞品分析要求是否落实
- 是否提供明确且可验证的差异化价值

### 2.18 质量审核 Skill

只有硬规则全部通过，且搜索意图、Methods、产品 Method、事实和可执行性达到阈值后才能交付。

### 2.19 保留强项审核 Skill

优化已有文章前，锁定 Quick Answer、use case、正确步骤、专业案例、FAQ 和有效结论。默认采用局部修改，不得把补充 Methods、修正 H 标签或加强产品场景化升级为全文重写。

## 3. 推荐调用顺序

`任务进入 -> SEO关键词分析 -> 初步搜索意图假设 -> SERP样本选择 -> 竞品内容分析 -> 搜索意图综合判定 -> 解决方案研究 -> Methods决策 -> 产品事实预校验 -> 场景化产品Method设计 -> Content Brief -> H标签规划 -> 大纲生成 -> 大纲审核 -> 分章节正文生成 -> 产品Method证据审核 -> 事实校验 -> SEO优化 -> 标准回审 -> 质量审核 -> 导出`

更新已有文章时，在 SEO 关键词分析之前先调用“保留强项审核 Skill”。

## 4. 统一 Skill 输出字段

- `name`
- `version`
- `purpose`
- `input`
- `depends_on`
- `output`
- `evidence`
- `checks`
- `failure_conditions`
- `return_to`
