# 内容生成通用标准体系 v4（融合版）

> 本文件是六类文章的共同标准入口。文章类型的专属结构和判定，必须同时读取 `08-多类型文章调度与共享标准_v1.md` 与 `types/` 中对应文件。How-to 的完整执行规范以 `07-How-to文章内容生成工作流_v5.md` 为准。

## 1. 适用范围与优先级

适用类型：`how_to`、`top_evaluation`、`vs`、`general_topic`、`alternatives`、`what_is_specs`。

规则优先级如下：

1. 可核验事实、用户安全与产品能力边界
2. 用户搜索意图与文章类型判定
3. 类型专属标准和市场/语言要求
4. 本通用标准
5. 转化、表达和篇幅优化

转化目标、关键词数量或既有模板都不得覆盖前四项。没有验证来源时，不能声称“已测试”、性能数值、用户评价、排名、获胜者或产品能力。

## 2. 六类文章共用的内容标准

### 2.1 任务与研究

- 任务先锁定文章类型、主题、市场、语言、目标读者、关键词表和可用 Product Catalog；市场/语言缺失时，在 SERP 研究前补齐。
- 先形成意图假设，再记录当前 SERP 前 10 个自然结果，并深度分析 3–5 个与意图相符的页面；旧文优化时加入自身页面。
- 每一篇文章独立建立研究护照：查询词、市场、日期、样本 URL、证据、`Must Cover`、`Must Improve`、`Differentiate`、`Product Proof`、`Avoid`、`Verify`。不得把一篇文章的结论、产品排序或分数复用到其他主题。
- 竞品用于理解需求、覆盖和差距，不能复制结构、照抄文案或将竞品营销主张当作事实。

### 2.2 关键词与 SEO

- 关键词服务于意图和章节任务；默认采用“意图驱动覆盖”，而不是固定密度或机械逐词插入。
- 每个关键词可标记为 `natural`、`manual_review` 或 `excluded`。不自然、偏离主题、会制造错误承诺的词不得强行使用。
- 每篇文章必须有唯一 H1，且 H2/H3 层级连续；Title、Meta、FAQ、内链建议和图片 alt 以实际交付要求为准。
- Quick Answer、定义、对比结论或选择建议应放在用户最需要的位置，不能为了 SEO 延迟回答核心问题。

### 2.3 证据与表达

- 将“事实”“基于证据的判断”“编辑建议/示例工作流”明确区分。
- 事实要保留可追溯来源、版本/地区/日期和适用边界；资料不足时删除、降级措辞或标记待核验。
- 不虚构实测、作者体验、案例、评分、价格、规格、前后对比或“最佳”结论。
- 每个正式结论都应说明适用场景、限制和反例；篇幅、清单和表格用于降低理解成本，不用于填充内容。

### 2.4 产品知识库与推荐

- 产品必须来自本任务给定的 Product Catalog 或已核验知识库；产品名不能成为选择文章类型、结构或结论的依据。
- 按类型和证据判定角色：`formal_method`、`ranked_candidate`、`comparison_subject`、`implementation_tool`、`ultra_tip` 或 `excluded`。
- 没有证据不预设自有产品为第一名、获胜者、唯一方案或必出现模块。产品不适配主任务时，只能作为边界透明的补充，或完全排除。
- 产品建议必须附带适配理由、来源状态、限制和推荐位置；不同产品、不同主题分别判断。

### 2.5 交付与质量闸门

交付给文章回审流程的内容必须包括：文章草稿、研究护照、关键词处理说明、证据/来源记录、产品角色决策、视觉需求清单、未核验项和类型专属检查结果。

以下任一情况阻断交付：类型错配；缺市场/语言即开始 SERP；H1 不唯一或标题跳级；无来源的关键事实；关键词硬塞；产品越界或强植入；复用其他主题的研究结论；缺少类型专属的核心模块；把视觉计划当作已交付图片。

## 3. 类型专属边界

| 类型 | 必须单独执行的核心判断 |
| --- | --- |
| How-to | 任务路径、方法候选池、步骤和异常处理 |
| Top | 入选范围、评估维度、排序证据与不确定性 |
| VS | 版本/地区锁定、同维度比较与结论条件 |
| 泛主题 | 子模式选择、解释范围、实体/场景覆盖 |
| Alternatives | 替代动因、可替代性、迁移成本与适用人群 |
| What Is & Specs | 直接定义、规格口径、版本、单位和限制 |

不得把 How-to 的 Methods 数量、Top 的排名、VS 的胜负结论，套用到其他类型。

## 4. 旧文增量更新

更新已有文章前，先锁定已有的正确 Quick Answer、有效步骤、案例、FAQ、结论和已验证事实。默认局部修复；只有主题偏离、关键事实失效或结构无法局部修复时才重构。任何新增模块须同步更新对应的摘要、表格、结论和内部链接。
