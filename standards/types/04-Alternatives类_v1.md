# Alternatives 类 Type Module v1.0

## 1. 适用标准

适用于“某产品/服务/方法的替代方案”“类似 X 的工具”“免费/开源替代品”等查询。读者已经知道原对象，任务是解释他们为什么寻找替代品，并给出按限制与使用场景匹配的可替代选择。

- 先核验原产品当前能力、价格/套餐、限制与常见迁移痛点；不得假设其缺点；
- 候选项必须能替代核心工作流或清楚说明只替代其中一部分；
- 入选与排序依据是替代场景，而不是是否为自有产品；
- 自有产品只有通过相同的 `ranked_candidate` 标准才能进入列表；不得使用“原产品很差”或无法证明的拉踩表述。

## 2. 类型流程

1. 建立 `Replacement Need Map`：读者要摆脱的成本、限制、工作流、平台、隐私、控制权或许可证问题。
2. 建立 `Alternative Set`：候选项的覆盖能力、迁移门槛、价格、平台、许可证、局限、证据与排除理由。
3. 按读者场景分组，不把“免费、开源、专业、创作者、企业”等标签当作空泛排名。
4. 先展示 Quick Picks 与公平比较，再写每项完整评估和选择建议。
5. 交接前复查每个“替代”是否真的对主工作流有替代价值。

## 3. 正文结构

1. Title / Meta / H1：说明替代对象、读者限制、年份仅在时效信息已核验时使用。
2. Introduction：界定为什么有人需要替代，而不夸大原产品问题。
3. Quick Picks 与 Comparison Table：按具体情境给出答案。
4. Why Look for an Alternative：只列本主题有证据支持的真实限制。
5. Best Alternatives by Use Case：每项使用一致结构——替代什么、Best for、关键优势、迁移/使用限制、价格与平台、证据说明。
6. How to Choose / Switching Considerations：兼容性、资产迁移、学习成本、商业授权和长期成本。
7. FAQ 与条件式结论。

## 4. 专属 Skill 与 QA

`Alternative Set Designer` 输出原对象痛点来源、候选池、替代范围、入选门槛、分类、场景推荐、排除理由和迁移风险。

失败条件：只是 Top 榜单换标题、没解释替代动机、候选项不能完成核心任务、为了推产品贬低原产品、将价格/免费/开源状态写成过期事实、没有迁移或授权边界。
