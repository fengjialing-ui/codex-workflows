# 内容交付契约与发布级验收 v1.0

> **状态：现行总闸门。** 本文件优先于各 Type Module 的交付命名规则。它不替代类型模块的研究与写作要求；它规定什么情况下可以开始、何时必须停止，以及什么才可以称为“完整交付”“终稿”或“可发布”。发布级的机器检查细则见 `11-可执行发布闸门与文件一致性_v1.md`，两者必须同时通过。

## 1. 先确定交付等级

每个任务启动时必须在任务简报中明确 `delivery_level`。不得默认把任意文章称为 Final。

| 等级 | 适用请求 | 允许交付 | 禁止命名 |
| --- | --- | --- | --- |
| `complete_draft` | 用户明确要初稿、研究稿或回审前材料 | 完整文章初稿 + Review Handoff Package | `FINAL`、终稿、可发布、Publish Ready |
| `publish_ready` | 用户说“完整交付”“终稿”“最终版”“可直接发布”或明确要求 DOCX/图片/QA | 本文件第 4 节的完整发布包 | 缺少任何 P0 项时使用 Final 命名 |

当用户未声明等级时：明确说“初稿、研究稿、仅 Markdown”时使用 `complete_draft`；本项目中请求“生成文章”且未限定初稿时默认 `publish_ready`，并在任务卡写明“按新文章终稿默认值执行”。不得把用户要求的完整文章擅自降级成只含交接材料的初稿。

## 2. 任务启动闸门（Gate 0）

每个单主题任务只需提供下列**最小输入**；执行者可自动生成 `task_id`。目标受众、核心搜索意图、方法数量与字数预算是研究和 Brief 的产出，而不是让用户预先猜测的字段。

```yaml
article_type: how_to | top_evaluation | vs | general_topic | alternatives | what_is_specs
topic: "主题 / 主关键词"
target_market: "国家或地区"
language: "交付语言"
delivery_level: complete_draft | publish_ready
keyword_table: "路径；若无则 null"
recommended_product: "名称、资料路径/URL；若无则 null"
```

以下内容是**可选约束**：SERP 设备、已知目标用户、品牌语气、目标 URL、内部链接、CTA、必须覆盖/禁止覆盖、图片限制、截止日期、指定字数。用户提供时必须遵守；未提供时，执行者在研究后提出建议并记录在 Brief，不得凭空将其伪装成用户要求。

**阻断规则：** `article_type`、`topic`、`target_market`、`language` 缺失时，不得进入 SERP 或正文。`delivery_level` 可继承上一段的新文章默认值；任务卡必须记录其来源。不得以“全球”“英文”等未经确认的假设替代。`keyword_table` 和 `recommended_product` 可以为空，但必须在 Keyword Map / 产品角色记录中如实标记。

项目级默认值只能在 `brief.md` 中明确写出，并且任务卡须写明“继承项目默认值”。

### 2.1 研究负责推导的字段

Gate 1 完成后，执行者必须在 `04_Content_Brief.md` 中写出并提供证据：

- 实际目标受众、任务场景和能力边界；
- 已确认/修正的核心搜索意图及其子意图；
- 用户问题、风险与决策变量；
- 推荐的文章架构、方法数量、字数预算和视觉范围。

这些结论必须来自关键词、SERP Top 10、深读样本与可验证来源；它们不是在任务开始时由用户承担的研究工作。

## 3. 研究与写作不可跳过的闸门

以下要求按**每个主题**独立执行。批量任务只能共享目录、字段、命名和检查程序，不能共享研究结论、候选方案、结构、正文、产品结论或评分。

### Gate 1：可审计 SERP 与机会矩阵

在写 Brief 前必须完成：

- 实际查询词、检索日期、目标国家/语言、设备和搜索环境；
- 自然 SERP Top 10：排名、标题、URL、页面类型；
- 3–5 篇相关页面的正文深读，而非标题或搜索摘要；
- `Must Cover`、`Must Improve`、`Differentiate`、`Product Proof`、`Avoid`、`Verify`；
- 每条结论能回链到具体页面或官方来源。

搜索摘要、未记录排名的链接、AI 概括或没有正文分析的结果列表均不构成完成的 SERP 研究。

### Gate 2：候选方案与产品角色

在写大纲前，必须建立候选方案池并说明每项的适用场景、前提、成本、难度、风险、限制、证据、保留/排除理由。主方法必须在操作路径、工具类别或适用场景上有实质区别；同一路径的改写不能计为多个方法。

推荐产品必须先判定为 `formal_method`、`ultra_tip` 或 `excluded`。只有存在由研究证实的真实相邻需求时，才能使用 `ultra_tip`；否则必须排除。产品不能因为被指定推荐而自动进入正文。

### Gate 3：结构、正文与关键词

文章结构必须由 Gate 1–2 产生。每个主方法必须写清：结论、`Best for`、不适用范围、准备条件、步骤、结果检查、优点和限制。Keyword Map 必须含关键词/聚类、优先级、推荐位置、实际位置、精确次数和覆盖状态；未覆盖或排除项必须说明原因。

### Gate 4：事实、视觉与发布检查

每个事实性主张、产品能力、价格、参数、案例、排名或“最佳”结论必须在事实核验表中标记来源、核验状态与处理方式。视觉不得以文字占位代替；发布级交付还必须通过实际 DOCX/PDF 页面渲染检查，并记录结果。

### Gate 0.5：发布能力预检（新文章 `publish_ready`）

在 SERP 前验证最终 Word、真实视觉和 DOCX 页面渲染能力。渲染器不可用时，应立即记录和告知用户；可以继续生成全部内容，但最终状态只能是 `Content Complete — Render QA Blocked`，不得在后续将其误称为发布级终稿。

## 4. `publish_ready` 完整交付包

`publish_ready` 必须包含以下文件。每个单主题一套；批量任务须有总索引并分别链接到各主题目录。

```text
00_最终交付包索引.md
01_节点产出与状态总表.md
02_关键词与搜索意图分析.md
03_SERP与竞品分析.md
04_Content_Brief.md
05_文章结构与关键词映射.md
06_完整文章.md
06_完整文章.docx
07_视觉资产与映射表.md
08_SEO发布信息.md
09_事实与来源核验表.md
10_完整流程执行报告.md
11_标准回审与质量报告.md
12_版本与修改记录.md
13_内容资产保留审计.md  （旧文回审时必填；新建文章明确标记 new_article）
14_终稿交付清单.md
qa-render.json  （与最终 DOCX 哈希匹配的页面渲染与具名 AI/人工检查记录）
assets/  （最终使用的图片及来源/生成记录）
```

文件不得用 README、简略链接清单、关键词摘要或空模板替代。DOCX 不是独立交付物；它必须与 `06_完整文章.md`、视觉映射表和 QA 结论一致。

在使用 FINAL、终稿、Publish Ready 或生成 ZIP 前，必须运行：

```powershell
.\tools\Test-ArticlePublishReady.ps1 -PackagePath <单主题包路径>
```

只有输出 `PASS — Publish Ready` 才能进入对外交付。`Test-PublishReadyPackage.ps1` 是外层文件预检，会继续调用该检查器；人工 QA 不能覆盖检查器的失败结果。

## 5. Final 命名与阻断状态

`11_标准回审与质量报告.md` 是发布级 QA 记录；新文章也必须填写，它不表示任务被路由为旧文回审。

下列任一项为 `Fail`、`Blocked` 或无法出示证据时，最终状态只能是 `BLOCKED — Not Publish Ready`：

1. Gate 0 输入不完整；
2. 无独立 SERP Top 10、3–5 篇深读与机会矩阵；
3. 无候选方案池或方法不独立；
4. 无完整关键词映射；
5. 无事实与来源核验表；
6. 无符合要求的视觉资产/映射；
7. 无 DOCX/PDF 页面渲染检查或检查失败；
8. 缺少第 4 节任一必需文件；
9. 批量主题存在共用研究、结构、方法理由、正文或评分。
10. `06_完整文章.md` 与 `06_完整文章.docx` 不等价、Word 残留 Markdown、来源/表格/图片 Alt 缺失，或渲染证据未匹配最终 DOCX 哈希；
11. 用户指定产品被排除或降级，但没有用户确认该商业范围变更。
12. 旧文回审没有 `13_内容资产保留审计.md`，未获批准压缩超过 30%，有效信息保留率低于 80%，或以审核说明/图片规划替代最终 Word；
13. 视觉资产未覆盖任务契约中指定的章节、图仅为文字卡/抽象占位，或 `14_终稿交付清单.md` 缺失。

只有所有项目通过，才可：

- 在文件名中使用 `FINAL`、`终稿` 或 `Publish Ready`；
- 对用户称为“完整交付”“最终稿”“可直接发布”。

## 6. 执行者的固定对外声明

### 启动时

```text
任务等级：{complete_draft / publish_ready}
本次将交付：{列出交付包或初稿包}
已锁定输入：{任务卡字段摘要}
当前阻断项：{无 / 缺失字段}
Final 命名资格：{尚未获得；须全部 QA 通过}
```

### 完成时

```text
最终状态：{Publish Ready / Complete Draft / BLOCKED — Not Publish Ready}
已通过闸门：{编号}
未通过项：{编号、原因、证据位置}
实际交付文件：{逐项路径}
Final 命名资格：{是 / 否}
```

不得用“已完成”“完整交付”“Final”等笼统表述掩盖未通过项。
