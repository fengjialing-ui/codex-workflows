# 泛主题类 Type Module v1.0

## 1. 适用标准

适用于没有单一操作路径或明确产品选择的泛知识、趋势、人物/作品、平台功能、背景问题和混合信息需求。它不是“什么都写一点”的兜底类型。

先将主题路由为一个子模式：`explainer`（解释概念）、`trend_context`（趋势/事件背景）、`entity_guide`（人物、作品、平台或功能导览）或 `problem_context`（问题成因、影响与选择）。子模式决定读者路径和信息边界。

## 2. 类型流程

1. 从 SERP、实体来源和目标受众中确认主问题及次问题。
2. 建立 `Entity & Narrative Map`：关键实体、关系、时间/版本、事实来源、争议或未知项。
3. 选择一个子模式和一条读者路径；避免混杂百科、教程、榜单与产品评测。
4. 只在读者理解主问题之后，判断产品是否为 `implementation_tool`、`ultra_tip` 或 `excluded`。
5. 完成完整初稿及事实/视觉 QA。

## 3. 正文结构

1. Title / Meta / H1 与 Answer-first Introduction。
2. Context / What readers need to know。
3. 按子模式展开：概念与机制、时间线/变化、关键实体/角色、真实场景、限制或争议。
4. Related choices, tips or applications：只保留对用户决策有用的内容。
5. 可选工具模块：必须是已解释问题的真实应用路径，不能替代主内容。
6. FAQ 与简洁结论。

## 4. 专属 Skill 与 QA

`Topic Narrative & Entity Mapper` 输出实体表、事实时间线、子意图、读者路径、边界、可选产品位置和信息缺口。

失败条件：用 How-to/Top/VS 标题硬拼内容、无来源的热门趋势或角色资料、以产品段取代主题答案、人物/作品资料与版本/地区不符、背景无限延展而没有用户问题主线。
