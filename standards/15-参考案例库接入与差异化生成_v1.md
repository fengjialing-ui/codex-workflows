# 参考案例库接入与差异化生成 v1.0

> **状态：现行可选标准。** 仅当任务或项目配置提供外部“文章内容案例库”或“文章结构案例库”时使用。本标准让案例成为按需参考的模式来源，不能将其变成固定模板、事实来源、产品预设或正文素材库。

## 1. 目的与边界

案例库可以帮助校准文章的完成度、读者路径、信息组织、表格和视觉的使用时机。它不能决定本篇文章的类型、结构、方法数量、产品位置、事实或结论。

- 原始案例保留在用户指定的外部目录中，默认只读；不得复制进 `standards/`、`examples/` 或最终交付包。
- 只记录案例的文件名、版本/日期、可复用的抽象模式与排除项；不得在运行记录中大段摘抄正文。
- 旧案例中的事实、产品能力、测试、价格、排名、用户观点和来源一律不是本次证据，必须重新核验。
- 案例中固定的 `Part 1–5`、固定 Methods 数量、固定 FAQ、固定 CTA 或无关产品段落，均不得自动继承。

## 2. 启动字段与接入时机

任务可选提供：

```yaml
reference_libraries:
  content_examples: "外部目录路径或 null"
  outline_examples: "外部目录路径或 null"
reference_usage: none | pattern_reference
```

没有明确提供路径时，不得猜测或扫描用户磁盘。提供后，在 **Task Router 和当前 SERP/竞品研究完成后、正式 Brief 前** 建立 `research/reference-pattern-intake.md`。先研究后参考，确保样例不会预设本篇文章的类型或答案。

## 3. Reference Pattern Intake

每份实际参考的案例必须记录：

| 字段 | 要求 |
| --- | --- |
| Reference file | 外部路径或稳定标识、文件日期、可读取状态 |
| Candidate type | 案例可能代表的类型，不是本篇路由 |
| Reusable pattern | 抽象到读者决策或信息关系，例如“先定义双方，再按迁移场景判定” |
| Explicit exclusions | 不可复用的固定章节、产品位置、测试主张、时效事实或文案 |
| Current-fit decision | `use_as_pattern` / `partial_reference` / `not_used` 与理由 |
| Evidence boundary | 当前 SERP、事实与产品资料仍为唯一可写依据 |

读取失败、损坏、市场/语言不符、类型不符或存在高复制风险的案例必须标记 `not_used`；不得为了“用上案例”而修复、改写或猜测其内容。

## 4. 差异化优先的结构决策

正式 Brief 必须在 `Reference Pattern Decision` 中说明：

1. 当前 SERP 的主导页面类型、共同覆盖与遗漏点；
2. 本篇读者的任务、决策变量和信息增量；
3. 是否参考某一抽象模式，以及本篇与它的实质差异；
4. 标题树、方法数量、比较维度、FAQ、表格、视觉和产品位置如何由本次研究决定；
5. 哪些案例特征被明确排除。

每篇至少应形成一个可验证的差异化贡献，例如新的场景分流、不同的诊断框架、经验证的限制说明、独立比较维度、当前来源整合或能减少用户误操作的视觉解释。单纯改写案例标题、交换章节顺序或增加泛泛段落不构成差异化。

## 5. 反同质化硬规则

以下任一情况均为 Plan/QA Fail，必须回流到研究或结构阶段：

- 以案例标题树、固定章节数或相同 Methods 顺序直接生成文章；
- 未完成当前 SERP 与事实研究就选择案例结构；
- 产品因案例中出现而自动进入本篇，或沿用案例 CTA/位置；
- 复用案例的开头、Quick Answer、FAQ、结论、表格行列、视觉说明或独特表达；
- 同类型连续文章使用相同的开头路径、H2 顺序、方法组合、产品段落或结论逻辑，却没有当前意图证据；
- 将案例中的历史测试、案例、数字、价格、排名或用户评价写成本次事实。

QA 必须建立 `Reference Differentiation Audit`，逐项检查：

```text
Reference use: none | pattern_reference
Current SERP completed before pattern selection: Pass | Fail
Article type independently routed: Pass | Fail
Original information gain: Pass | Fail
Title-tree / method-order similarity: Pass | Fail
Product-position independence: Pass | Fail
No copied prose, tables, FAQ, CTA, or visuals: Pass | Fail
```

## 6. 类型化模式，而非模板

可以参考的模式只描述关系，不规定文字或章节名称。例如：

| 类型 | 可参考的抽象模式 | 不可固定化的项目 |
| --- | --- | --- |
| How-to | 诊断 → 场景选择 → 操作 → 验证 → 防错 | 方法数量、顺序、工具和产品位置 |
| Top | 候选范围 → 标准 → 分场景选择 | 候选名单、排名、评分、实测结论 |
| VS | 定义对象 → 相同维度比较 → 场景判定 | 比较维度、胜者、Bonus 产品 |
| Alternatives | 替代动因 → 替代类别 → 迁移条件 | 替代名单、产品排序、CTA |
| What Is & Specs | 定义 → 规格/边界 → 场景选择 | 固定术语表、参数、实施工具 |
| General topic | 读者问题 → 子主题/实体 → 解释与边界 | 固定叙事路径、人物/产品段落 |

同类型文章可参考同一类模式，但必须在本次 SERP 证据、目标读者和差异化贡献的约束下重建实际标题树和内容逻辑。
