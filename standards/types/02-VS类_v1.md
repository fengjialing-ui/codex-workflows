# VS 类 Type Module v1.0

## 1. 适用标准

适用于两个或多个明确实体的比较与选择。核心回答是“哪一个更适合哪类用户”，不是为了转化而宣布一个无条件胜者。

- 比较对象、版本、套餐、地区和时间点必须先锁定；
- 只比较读者能够据此做决定的同类维度；不能把一个产品的优点和另一产品不相关的功能放在同一行；
- 每个维度允许 `A wins`、`B wins`、`depends` 或 `insufficient evidence`；
- 性能/实测模块只有在拥有记录的测试环境、素材、版本、指标、原始结果和限制时才能进入正文；
- `comparison_subject` 不等于推荐产品，结论必须由本次比较证据得出。

## 2. 类型流程

1. 明确比较意图：用户为什么在此刻比较这几个实体。
2. 建立 `Decision Matrix`：维度、用户关心原因、证据来源、各对象事实、结论及置信度。
3. 对价格、功能、兼容性、隐私、迁移成本、易用性、质量/性能等动态字段逐项核验。
4. 将维度结论转为场景建议；若需要测试，先设计再执行测试，不能先写结论后补数据。
5. 完成初稿与 QA，明确所有未决或版本差异。

## 3. 正文结构

1. Title / Meta / H1 与 Introduction：首段直接给出条件式答案。
2. Quick Decision：`Choose A if… / Choose B if… / Neither if…`。
3. At a Glance Table：最关键的 4–7 个可比维度。
4. Brief Overview：对两个对象使用完全对称的背景、定位、限制和 Best for。
5. Feature-by-feature Comparison：按维度而非“先写完 A 再写 B”；每节有对比事实和简洁结论。
6. Real-world Scenarios / Test Results：仅在证据充分时出现。
7. Recommendation by User Type、FAQ、Final Verdict。

## 4. 专属 Skill 与 QA

`Decision Comparison Designer` 输出可比性检查、维度表、场景胜者、平局/不确定项、测试设计及结论证据。

失败条件：强行宣布总冠军、事实只核验一方、把社区观点写成事实、比较表与正文结论矛盾、产品插入抢走主比较结论、无测试却使用“实测/速度更快/效果更好”。
