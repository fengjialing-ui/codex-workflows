# 可执行发布闸门与文件一致性标准 v1.0

> **状态：现行强制标准。** 本文件补足 `00-交付契约与发布级验收_v1.md` 与 `13-新文章生成终稿闭环_v1.md` 的可执行检查。旧文回审还必须执行 `12-旧文回审与终稿交付保障_v1.md`。发布级任务必须通过 `tools/Test-ArticlePublishReady.ps1`；人工在 QA 表中写 `Pass` 不能替代检查器的结果。

## 1. 不可绕过的顺序

`发布能力预检 → 研究证据 → Brief/方案池 → 正文与关键词 → 实际视觉资产 → Markdown→DOCX 转换 → 同一 DOCX 的结构与无障碍检查 → 同一 DOCX 的页面渲染与人工页面检查 → 发布预检 → FINAL 命名/压缩包`

任一阶段失败时：

- 停止后续阶段和对外打包；
- 在 `11_标准回审与质量报告.md` 记录责任阶段、问题、证据和回流动作；
- 只可交付 `Complete Draft` 或 `BLOCKED — Not Publish Ready`，不得以“内容包完整”“结构复核版”或 ZIP 文件绕过 Final 资格。

不得用另一份 DOCX、后来生成的“复核版”、旧的渲染截图或未匹配哈希的报告，为 `06_完整文章.docx` 背书。

## 2. 每个发布包必须增加的可机器核验记录

### 2.1 `03_SERP与竞品分析.md`

自然结果表必须含：`Natural rank`、`Title`、`URL`、`Page type`；必须有 1–10 共十条。另记录检索词、日期、市场、语言、设备、搜索环境。不得用 `Capture order` 替代 `Natural rank`。

每个深读样本须含 URL、页面类型、正文观察、具体覆盖/改进/风险结论；至少三篇。搜索摘要不是正文观察。

### 2.2 `04_Content_Brief.md`

必须写入：

```text
Validated target word range: {min}–{max} English words, excluding sources and tables
Validated narrative word count: {actual}
Recommended product supplied: {name | none}
Product decision: {formal_method | ultra_tip | excluded}
Product-resolution status: {not_needed | user_confirmed | blocked_waiting_for_user}
```

若用户指定推荐产品但研究判定为 `excluded`，或只能作为与主任务不相邻的内容，必须标记 `blocked_waiting_for_user` 并停止。执行者必须向用户给出可选方向：换主题、换产品、允许边界说明、或明确不要求产品露出。没有用户确认不得写正文或进入 Final。

方案池除了纳入方法，还必须为每个 SERP 中有实质决策价值的方案类别记录 `included` 或 `excluded`，并列出适用场景、限制、风险、证据及理由。排除不是不记录。

### 2.3 `05_文章结构与关键词映射.md`

必须有一行与任务卡完全一致的主关键词。该行必须含正文自然位置、精确次数与 `Covered` 状态；只出现在文件元数据、关键词表、来源或图片名不算正文覆盖。

`formal_list` 的高优先级词不得批量标为排除。若超过 20% 高优先级词被排除，必须回流到意图/范围决策并要求人工确认；不得将“排除”用作批量完成状态。

文章发布前必须使用正文重新计算字数；不得引用草稿时的计数。实际字数低于 Brief 下限即阻断。

### 2.4 `06_完整文章.docx`

这是唯一可发布 Word 文件。它必须和 `06_完整文章.md` 保持内容等价：标题、正文模块、决策表、方法、FAQ、结论、来源与实际视觉均不能缺失。

禁止将 Markdown 语法原样写入 Word（例如 `**粗体**`、反引号、`![图片]()`、`[标题](URL)`）。表格必须是 Word 表格；来源必须是可点击链接；每张实际图片必须有有意义的 alt 文本。

标题层级必须在 Markdown 与最终 Word 中逐项一致，不能只检查 Markdown：

- Markdown 必须恰有一个 `# H1`；最终 Word 也必须恰有一个语义 `Heading 1`，且该段文字与 Markdown H1 一致。文章标题不得仅是 `Normal` 段落、封面文字或直接格式化的字号。
- Markdown 的 `##` 必须逐项映射为 Word `Heading 2`；`###` 必须逐项映射为 Word `Heading 3`。标题的数量、顺序、文本和级别均须一致。
- H2 只能用于同级文章模块/Methods；H3 只能用于其下的子问题、步骤组或 FAQ 问题。不得从 H1 跳到 H3，也不得把 Quick Answer、方法、FAQ、Conclusion、Sources 等 H2 错设为 H1。
- `tools/Test-ArticlePublishReady.ps1` 无法解析或无法通过上述 DOCX 标题审计时，必须以 P0 阻断；人工 QA 的“通过”不能覆盖该失败。

### 2.5 `qa-render.json`

渲染完成后必须生成以下记录，并针对**同一个** `06_完整文章.docx`：

```json
{
  "status": "pass",
  "source_docx_sha256": "<SHA-256>",
  "renderer": "render_docx.py / equivalent",
  "rendered_at": "YYYY-MM-DDThh:mm:ssZ",
  "page_count": 1,
  "page_files": [{"path": "internal/page-1.png", "sha256": "<SHA-256>"}],
  "reviewed_by": "Codex",
  "inspection": "All pages inspected at 100%; no clipping, overlap, broken table, missing glyph, or misplaced figure/footer."
}
```

`status` 不为 `pass`、DOCX 或任一页面文件哈希不匹配、页面文件不存在、页数不一致、页数为 0 或没有人工检查结论时，发布级状态必须为 Blocked。渲染器缺失是阻断，不是豁免。

## 3. 检查器与人工检查的职责

`tools/Test-ArticlePublishReady.ps1` 检查可客观验证的项目：文件齐全、SERP 表头和数量、Brief 字数、主关键词、Keyword Map、Markdown/Word 的唯一 H1 与逐项标题层级映射、Word/Markdown 的表格与来源数、残留 Markdown、Word 超链接、图片 alt 文本、渲染证据哈希和 QA 状态。

检查器无法判断的项目——SERP 正文是否真的读过、方案是否覆盖全部有价值场景、事实是否被正确解释、图片是否真正帮助理解、页面审美和产品策略是否合理——必须由 R1–R5 人工逐项记录。任何一项未通过都应写入 QA 的 `Fail` 或 `Blocked`，使检查器阻止 FINAL 命名。

## 4. 版本与交付纪律

- `06_完整文章.md` 与 `06_完整文章.docx` 修改后，所有字数、结构、无障碍、渲染和预检都必须重跑。
- 若 Word 文件被占用而无法覆盖，保留原文件并立即将任务设为 Blocked；不得用另存为复核版代替最终文件。
- ZIP 只能在检查器返回 `PASS — Publish Ready` 后生成；ZIP 内包含的 `qa-render.json` 和 `11_标准回审与质量报告.md` 必须是本次的最终记录。
- 对外完成声明必须逐字采用检查器结论；检查器失败时，声明只能为 `BLOCKED — Not Publish Ready`。
