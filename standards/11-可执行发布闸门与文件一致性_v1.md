# 可执行发布闸门与文件一致性标准

当前执行版本见根目录 workflow.json。文件名 v1 保持兼容；本文件规定发布机械检查，内容研究与写作标准继续由 00、08、对应 Type Module、12/13 负责。

## 顺序与入口

按 EXECUTION.md 初始化 tools/workflow_state.py，并依次推进 scope、research、plan、content、assets、document、qa。缺少前置阶段、输入或产物变更均阻断发布；不得手改状态记录。
正式发布命令：`python tools/validate_article_package.py --package RUN_DIR`。
两个旧 PowerShell 发布脚本保留为调用同一 Python 检查器的兼容入口，任选其一即可，不再重复跑同一检查。

## 实际检查

- 所有约定交付文件存在非空，清单与任务目录实际文件一致；新文件通过 manifest 明确登记。
- 主查询自然结果具有唯一 1–10 排名、Title、URL、Page type；检索词、市场、日期可追溯。其他核心词的 SERP 表单独保存并在阶段证据中登记；每个深读样本仍需正文观察，至少三篇。不得以搜索摘要代替正文证据。
- 文章类型沿用 08 的 how_to、top_evaluation、vs、general_topic、alternatives、what_is_specs。产品角色按类型选择：formal_method / ranked_candidate / comparison_subject / implementation_tool / ultra_tip / excluded；指定产品被排除时仍需用户确认。
- release-manifest.json 明确任务模式、主关键词、研究确定的字数区间、实际叙述字数、SEO metadata、产品角色与来源、配图范围、人工批准政策。示例见 templates/release-manifest.example.json。
- 实际叙述字数排除 SEO 元信息行、Markdown 表格、独立图片行及 Sources 段；使用检查器的 narrative_count 函数重算。非英语字数口径须在 Brief 说明，不能伪称英语 words；有特殊分词需求时保留完整内容并调整经研究验证的区间与说明。
- 完整比较 Markdown 与 Word 的正文/表格文字顺序、唯一 H1、全部标题级别及链接目标；必须保留 Word 表格。呈现标点和空白允许差异，内容词和数字不得丢失。引用式链接、脚注、HTML 表格需先导出可验证的规范 Markdown；不支持的结构会明确失败。
- SEO title、meta description、slug 必须存在于最终 Word。主关键词在 H1 自然出现或有明确语义替代说明，并在关键词映射中保留；原始所有词有处置记录，不能用无关高量词充数。
- 即时答案和视觉范围根据类型与任务确定。How-to 需要明确的即时答案位置；不要求所有类型都使用固定英文 Quick answer 标题，也不靠 Method 编号猜图片数量。
- 每张约定图片真实存在、格式可识别、哈希与嵌入 Word 的图一致；具备准确 Alt、图注、章节和用途。没有图片的范围必须由任务要求明确，不能用该选项绕过已要求的配图。
- 原文优化默认保留有效资产，压缩超过 30% 或有效信息保留低于 80% 时需明确授权；重写模式需用户授权引用。

## 渲染证据

qa-render.json 必须包含 status、source_docx_sha256、page_count、page_files（每页 path 和 sha256）、reviewed_by、reviewer_type（ai/human）、inspection。所有页面文件需真实存在、可识别为图片，且与最终同一 DOCX 的哈希匹配。样例见 templates/qa-render.example.json。
渲染缺失或不匹配时，状态为 Content Complete — Render QA Blocked，禁止 Final。能力预检只检查可执行程序是否存在，不代替真实渲染。

## 内容复核与人工批准

editorial-qa.json 逐项记录意图、结构、关键词自然度、产品事实、来源、视觉、文档质量；旧文另加资产保留。每项包括 result、finding、evidence。AI 复核必须标 ai，不得冒充人工。
本次或项目政策要求真实人工批准时，human_approval_required 为 true，并记录实际批准者和证据；否则不增加额外人工停点。自动检查不能证明 SERP 真实性或审美判断正确，仍需具名内容/视觉复核。

## 交付

发布检查输出保存到任务目录之外，避免报告自身进入被检查清单的循环。修复后重跑；通过后再生成 ZIP，ZIP 放在任务目录之外。旧任务缺少新字段或阶段证据时不会自动升级为 Final；复用有效内容，重新核验缺失步骤。

关键词展示要求在 task-contract.json 冻结为 keyword_visibility：not_requested / report_only / yellow_highlight；需要高亮时在 manifest 指定 keyword_highlight_terms，并验证这些词在最终 Word 中实际为黄色。
